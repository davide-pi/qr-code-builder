# i18n

Home-grown, dependency-free. Languages: `en`, `it`, `ro`.

## Structure

| File | Role |
|------|------|
| `src/i18n/types.ts` | `Language` union, the `Translations` interface (the single schema), `LANGUAGE_STORAGE_KEY` |
| `src/i18n/en.ts`, `it.ts`, `ro.ts` | One `Translations` object each |
| `src/i18n/LanguageContext.tsx` | `LanguageProvider`: initial language (saved choice, else `navigator.language`: `it`, `ro`, otherwise `en`), `setLanguage` (saves it, sets `<html lang>`) |
| `src/i18n/useLanguage.ts` | `useLanguage()` returns `{ language, setLanguage, t }`; `availableLanguages` feeds the header switcher |
| `src/components/Flags/Flags.tsx` | Flag of each UI language (3 SVGs from `flag-icons`) |

Top-level sections of `Translations`: `header`, `qrDataInput` (categories, template names, form labels,
validation `errors`), `qrOptions`, `qrPreview`, `batch`, `footer`, `common`, `pwa`.

Usage: `const { t } = useLanguage();` then `t.qrPreview.title`. Strings with variables use `{name}` placeholders
replaced at the call site (`t.qrOptions.presets.saved.replace('{name}', name)`).

## Parity rule

Every user-visible string goes through `useLanguage()`, and a key is added to `types.ts` **and** to all of
`en.ts`, `it.ts`, `ro.ts` in the same change. Parity is enforced by the compiler, not by a test: each
dictionary is typed `Translations`, so a missing or extra key fails `npm run build` (`tsc -b`). Validation
messages are typed from the dictionary too (`ErrorKey = keyof Translations['qrDataInput']['errors']`), so a
template cannot return an error that has no translation.

## Add a key

1. Add it to the `Translations` interface in `src/i18n/types.ts` (inside the right section).
2. Add the value to `en.ts`, `it.ts` and `ro.ts`.
3. Use it as `t.<section>.<key>`.
4. `npm run build` must pass.

Accessibility strings count: every image and icon-only button needs a translated label (`aria-label`).

## Add a language

1. `types.ts`: extend the `Language` union.
2. New `src/i18n/<code>.ts` exporting a full `Translations` object.
3. `LanguageContext.tsx`: add it to `translations`, to the `stored === ...` check in `getInitialLanguage` and to `detectBrowserLanguage`.
4. `useLanguage.ts`: add `{ code, name }` to `availableLanguages` (name in its own language).
5. `Flags.tsx`: import its flag (`flag-icons/flags/4x3/<cc>.svg`) and add it to `flagSources` (typed `Record<Language, string>`, so the compiler reminds you).
6. Batch (`components/Batch/`): the template CSV uses `,` for English and `;` for every other language; `parseBoolean` in `batchRows.ts` accepts yes/no words of the existing languages (`si`, `vero`, `da`, `falso`, `nu`...): add the new language's words.
7. Country names in the phone selector need no change: they come from `Intl.DisplayNames` with the language code as locale.
8. `npm run build`, then check the language menu by keyboard.
